# メタオリパ パック作成手順

この手順は「メタオリパ 構築」スプレッドシート（過去パック30シート以上）の式と構成、
週次MTG（2026/09/23）の方針から整理したもの。
本荘征悟さんの「パック作成マニュアル（2026/09/30）」との突き合わせはまだなので、
マニュアルと違う点があればこのファイルとツールの既定値を直すこと。

## 1. 作り方（30分を目標）

1. **テーマと価格帯を決める**
   - 目玉（S爆）にする在庫カードを決める。仕入済みのカードを優先して回収する。
   - 一回の価格と総口を決める（下の「過去パック早見表」を参考に）。回しやすい少額にする。
   - 競合が同じテーマを出していないか確認する。競合サイトの一覧は [competitors/](competitors/README.md)（2026-10-14時点・267件）。
2. **カードを集める**
   - S爆を3〜4枚、S賞を6〜10枚。スニダンで仕入れ価格とURLを調べる。
   - **当たりは全部PSA10**（必須）。仕入れ価格もPSA10の値段で調べる。
   - スプレッドシートにまとめた場合は CSV に書き出してそのまま使える
     （見出し: `賞,名称,URL,仕入れ価格,数量,配送のみ,在庫,掛け率,メモ`）。
3. **パック定義ファイルを作る**
   - `packs/template.toml` をコピーして `packs/日付_ガチャ名.toml` を作り、カードを入れる。
   - Claude Code に「このカードでパックを作って」と頼めば、定義ファイル作成から実行まで任せられる
     （`.claude/skills/oripa-pack/SKILL.md`）。
4. **実行する**
   ```
   python -m oripa packs/2026-10-07_xxx.toml
   ```
   - 画面に構築表・還元率・概算収支が出て、`out/2026-10-07_xxx.xlsx` ができる。
   - 還元率が上限（既定100%）を超えるとエラーで止まる。
5. **確認して登録する**
   - xlsx の「構築」シートを構築スプレッドシートに取り込み（ファイル → インポート → 新しいシートを挿入）、
     村佐さんに確認してもらう。
   - 「当選番号」シートの順にサイトへ登録する。

## 2. 構築ルール（構築シートから）

### 賞の構成
| 賞 | 中身 | 枚数の目安 | 備考 |
| --- | --- | --- | --- |
| S爆 | 目玉の高額カード（PSA10） | 3〜4枚 | **配送のみ**（ポイント交換不可） |
| S | 中額カード | 6〜10枚 | ポイント交換可 |
| A | ポイント交換（一回の価格より高いPT） | 残りの1〜3割 | ここが「アド」。枚数で還元率を調整する |
| B / C | ポイント交換（低いPT） | 残り全部 | 最低保証。1PT〜一回の半額程度 |

当たり（S爆＋S）はだいたい10枚前後、ハズレ枠は1〜2種類。

**当たり（S爆・S）は全部PSA10にする（必須・2026/10/14〜）。** 未開封BOX・パック・素のカードは当たりに入れない。
過去の構築シートにはBOXガチャもあるが、これからは作らない。

**課金ガチャは、最低PTを課金額と同じにする（2026/10/26〜）。** 1,000円課金なら、ハズレ枠は最低1,000PT。
定義ファイルに `charge_gacha = true` を書くと、ハズレ枠のPTが一回の価格より低いときにエラーになる。
- そのぶん還元率は必ず100%を超える。還元率 ＝ 1 ＋（当たりのPT合計 − 当たり枚数 × 一回）÷ 総PT。
- 例：1,000円×5,000口で還元率110%以内なら、当たりのPT合計は約50万PTまで（仕入れ約34万円の目玉1枚ぶん）。
  当たりを増やすなら総口を増やすか、還元率の上限を相談する。

### PT（付与ポイント）の計算
```
PT = 仕入れ価格 × 1.05 × 掛け率  を500円単位に切り上げ
     （1000未満の端数が500以下なら500、500超なら次の1000）
```
- 掛け率: S爆 1.4（高額の目玉は 1.45〜1.5）、S 1.3。
- 過去のBOX・パック商品は掛け率を個別に指定していた（×1.25、×1.3 など）。今はBOXを当たりに入れない。
- シートの式: `=LET(x,D3*1.05*1.4,y,MOD(x,1000),IF(y<=500,x-y+500,x-y+1000))`

### 当選番号
- 当たりカード1枚ごとに 1〜総口 の番号を重複なく割り振る。ハズレ枠は「ランダム」。
- **高いカードほど後ろの番号にする。一番高いカードは総口の9割以降の番号にする**（2026/10/13〜）。
  - ツールは乱数で番号を引いてから、PTの安いカードから順に小さい番号を割り当てる。
  - 一番大きい番号が9割に届かなければ、その番号だけ9割以降から引き直す（`top_number_from` で割合を変えられる）。
- `seed` を変えると番号が変わる。

### 収支の見方（構築シートと同じ定義）
| 項目 | 式 |
| --- | --- |
| 総PT | 一回 × 総口 |
| 構築PT | 全カード・ハズレ枠の PT × 枚数 の合計 |
| **還元率** | 構築PT ÷ 総PT |
| 差額 | 総PT − 構築PT |
| 配送のみ利益 | 配送のみカードの（PT − 仕入れ価格）の合計 |
| 期待課金額 | 配送のみカードの PT の合計 |
| クーポン利用後課金額 | 期待課金額 × 0.97 |
| **概算収支** | 差額 ＋ 配送のみ利益 ＋（クーポン利用後課金額 − 期待課金額） |
| 粗利率 | 概算収支 ÷ クーポン利用後課金額 |
| アド確率 | 総口 ÷（一回の価格より高いPTが出る口数）→「1/◯」 |
| 新規仕入額 / 在庫活用額 | 当たりカードの仕入れ価格を「在庫」かどうかで分けた合計（ツール独自） |

## 3. 方針（週次MTG 2026/09/23・09/30）

- **当たりは全部PSA10**（2026/10/14 槌田さん）。
- **課金ガチャは最低PT＝課金額**（2026/10/26 槌田さん）。
- **還元率は100%以下**。超える場合も赤字は少なめに（課金ガチャ・お詫びガチャで上げる時だけ `max_return_rate` を変える）。
  - 過去に「1/10 高還元ガチャ」（還元率110.9%）で概算収支 −5,079,705 が出ている。
- **回しやすい少額・少回数の価格帯**で作る。
- **仕入済みカードを目玉**にして在庫を回収する（`stock = true`）。仕入が売上を上回っているため。
- 上乗せは20〜25%が目安。それ以上乗せると評判が悪くなる（構築シートのメモ）。
- 目標: 3人で手分けして毎日1本出す（1人3日に1本）。
