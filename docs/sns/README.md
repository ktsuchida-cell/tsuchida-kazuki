# X投稿の分析と作成（@metaoripa_）

メタオリパの X アカウント（[@metaoripa_](https://x.com/metaoripa_)）の投稿を、

1. **分析する**: 過去の投稿から、種類ごとの割合・反応のよい書き方・時間帯・お手本を出す
2. **作る**: パックの構築結果から、数字の入った告知文のたたき台を作る（Claude Code が文体を整える）
3. **確かめる**: 文字数・NGワード・パックの数字との食い違いを、投稿前に止める

ための仕組み。投稿そのものは人が確認して行う（自動投稿はしない）。

## 全体の流れ

```
投稿データ（sns/posts/） ──analyze──▶ docs/sns/投稿分析.md（自動で作る）
                                          │ 読んで直す
                                          ▼
                     sns/rules.toml・sns/templates/・docs/sns/スタイルガイド.md
                                          │
パック定義（packs/*.toml） ──draft──▶ たたき台（数字は構築結果から入る）
                                          │ Claude Code が文体を整えて2〜3案に
                                          ▼
                                   check（文字数・NGワード・数字）──▶ 人が確認して投稿
```

数字（1回の価格・総口・アド確率・還元率）は構築結果から入れるので、手で打ち間違えない。
文体はテンプレートとスタイルガイドで決め、実際の投稿の分析に合わせて直していく。

## ファイル

| ファイル | 中身 | 誰が直す |
| --- | --- | --- |
| `sns/posts/` | 書き出した過去の投稿データ | 人が置く |
| `sns/rules.toml` | 投稿の種類と判定キーワード・ハッシュタグ・NGワード・文字数の上限 | 分析を見て直す |
| `sns/templates/<種類>.txt` | 投稿のテンプレート（`---` だけの行で区切って何案でも） | 分析を見て直す |
| `docs/sns/投稿分析.md` | 分析結果（`analyze` が作る。手で直さない） | 自動 |
| `docs/sns/スタイルガイド.md` | 書き方のルール | 分析を見て直す |
| `oripa/sns/` | ツール本体 | — |
| `.claude/skills/x-post/` | Claude Code に「告知文を作って」と頼んだときの手順 | — |

## 1. 投稿データを入れる

Claude の作業環境からは x.com を開けない（ログインが要る）ので、投稿は書き出して `sns/posts/` に置く。
どれか1つでよい。複数置けば合わせて読む（同じ投稿は1つにまとめる）。

| 方法 | 置くファイル | 入っているもの |
| --- | --- | --- |
| **X のデータアーカイブ**（おすすめ） | `tweets.js` | 全部の投稿・日時・いいね・リポスト・画像の有無。インプレッションはない |
| X のアナリティクスの書き出し | `*.csv` | 投稿・インプレッション・いいね・リポストなど（期間を選んで書き出す） |
| 手で貼る | `*.txt` | 投稿を `---` だけの行で区切る。先頭に `日時: 2026-10-24 19:00` `いいね: 12` `リポスト: 3` `表示: 1500` を書ける |

- データのアーカイブは X の「設定とプライバシー」→「アカウント」→「データのアーカイブをダウンロード」から申請する（届くまで時間がかかる）。
  zip の中の `data/tweets.js` **だけ**を `sns/posts/` に置く。zip にはDMやログイン履歴も入っているので、zip ごと置かない・コミットしない。
- CSV の見出しは英語（`Post text`・`Date`・`Impressions`・`Likes` …）でも日本語（`本文`・`日時`・`表示回数`・`いいね` …）でも読める（`oripa/sns/posts.py` の `CSV_COLUMNS`）。
- 返信とリポストは分析から外す。

## 2. 分析する

```
python -m oripa.sns analyze            # sns/posts/ を全部読む → docs/sns/投稿分析.md
```

投稿分析.md に出るもの:

1. 投稿の種類（新ガチャ告知・当選報告・残り口数・プレゼント企画・お知らせ・その他）ごとの件数・文字数・画像つき・反応
2. 投稿の時間帯・曜日ごとの件数と反応
3. 書き方（文字数・行数・絵文字・【】の見出し・ハッシュタグ・書き出しと締めでよく使う形）
4. 反応がよかった投稿（上位10件）
5. 種類ごとのお手本（反応の上位3件）← 投稿文を作るときの見本
6. 反応が少なかった投稿（下位5件）

反応は、インプレッションがあれば「エンゲージメント率」（いいね＋リポスト＋返信＋ブックマーク ÷ 表示）、なければ「いいね＋リポスト」で比べる。

分析を見たら、`sns/rules.toml`（種類のキーワード・ハッシュタグ）、`sns/templates/`、`docs/sns/スタイルガイド.md` を実際の書き方に合わせて直す。
Claude Code に「Xの投稿を分析して」と頼めば、ここまでやる。

## 3. 投稿文を作る

```
python -m oripa.sns draft packs/2026-10-13_dragon_psa10_5000.toml --type 新ガチャ告知
python -m oripa.sns draft packs/xxx.toml --type 残り口数 --remaining 1200 --set "left=・カメックスEX SR PSA10"
python -m oripa.sns draft packs/xxx.toml --type 当選報告 --set "card=カメックスEX SR PSA10"
python -m oripa.sns draft --type プレゼント企画 --set prize=1,000PT --set winners=10 --set "deadline=11/3（火）23:59"
```

- テンプレートの案ごとに、本文・文字数・チェック結果が出る。`-o out/sns/xxx.txt` でファイルにも書き出せる。
- 埋まらない項目（`{card}` など）はそのまま残り、チェックでエラーになる。`--set 項目=値` で埋める。
- Claude Code に「このパックの告知文を作って」と頼むと、たたき台をスタイルガイドとお手本に合わせて2〜3案に書き直し、チェックまでする。

### テンプレートで使える項目

| 項目 | 中身 | 例 |
| --- | --- | --- |
| `{name}` | ガチャ名（パック定義の name） | ドラゴン PSA10ガチャ |
| `{price}` / `{draws}` | 1回の価格 / 総口 | 5,000 / 3,000 |
| `{hits}` / `{hits_line}` | 当たりの枚数 / 当たりが全部PSA10かどうかの1行 | 10 / 当たり10枚は全部PSA10 |
| `{top}` | 一番高い当たり | レシラム&リザードンGX SA PSA10 |
| `{top_tier}` | 一番上の賞（S爆）の一覧（1行1枚） | ・レシラム&リザードンGX SA PSA10 |
| `{lineup}` | 高い順に5枚 | |
| `{ad_odds}` | アド確率。分母は0.1単位で**切り上げ**（当たりやすく見せない） | 1/4 |
| `{min_pt}` | 最低保証のPT（ハズレ枠の一番低いPT） | 2,500 |
| `{ad_line}` | 「アド確率 ◯・最低保証 ◯PT」。課金ガチャ（最低保証が1回の価格以上）は「最低保証 ◯PT」だけ | アド確率 1/4・最低保証 2,500PT |
| `{return_rate}` | 還元率（%）。0.1%単位で**切り捨て** | 96.9 |
| `{url}` / `{account}` / `{hashtags}` | rules.toml のサイトURL（`--url` で変更）/ アカウント / ハッシュタグ | |
| `{remaining}` | `--remaining` の残り口数 | 1,200 |
| そのほか | `--set 項目=値` で入れる（`{card}` `{left}` `{prize}` `{winners}` `{deadline}` など） | |

カード名の `[CP6 092/087]` のような型番は投稿では外す。

## 4. 確かめる

```
python -m oripa.sns check out/sns/xxx.txt --pack packs/xxx.toml [--remaining 1200]
```

| 種類 | 内容 |
| --- | --- |
| エラー | X の数え方で280を超える（日本語・絵文字は2、URLは23）／`{card}` などが埋まっていない／NGワード（換金・稼げる・必ず当たる など） |
| エラー（`--pack` のとき） | 「1回◯PT」「全◯口」がパックと違う／還元率・アド確率が実際より良い／当たりにPSA10でないカードがあるのに「全部PSA10」／「残り◯口」が `--remaining` と違う |
| 注意 | 「確定」「残りわずか」「期間限定」「No.1」「高還元」「プレゼント」「無料」など、使うときに確かめる言葉／ハッシュタグが多い／残り口数（`--remaining` がないとき） |

NGワード・注意ワードは `sns/rules.toml` で足せる。法的な判断が要るものは担当者・専門家に確認する。

## 今はやらないこと

- x.com からの自動取得・自動投稿（X API の有料プランが要る。料金は要確認）。今は書き出したデータを置く。
- 告知画像（バナー）の作成。
- 投稿後の反応の追跡。新しい投稿データを置いて `analyze` をやり直せば、分析は更新される。
